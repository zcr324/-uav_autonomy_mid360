# UAV 框架整合与实验交付记录 · 2026-10-22

## 当前结论

框架已能统一启动仿真、前端定位、后端、EGO、控制和任务验证，实际完成过飞行建图、实体绕障往返和一条约63.7m的隧道闭合路线，能够导出真正由传感器重建的点云。

**真实回环优化尚未验收通过。** STD 已检测到真实重访候选，PGO 能收到并检查，但本轮已接受约束数始终为0。因此不能声称已经看到“回环优化后地图变好”。后端路径和地图文件确实存在，只能证明后端计算与输出链路工作。

按预定停止条件，长路线定位失败、几何细化未通过和6圈定点复访未接受回环均保留失败结果，不再反复放宽参数追求通过。本轮全部项目操作均在 WSL。

## 1. 六个模块现在怎样分工

|模块|来自谁、现在如何使用|
|---|---|
|仿真与传感器|框架的Gazebo/PX4，加组长交付的MID360 Driver2模型和插件副本|
|前端定位|使用LTA-OM内置FAST-LIO，因为它带后端修正接口；组长独立FAST-LIO2保留为对照基线|
|后端|现有LTA-OM的STD检测与GTSAM图优化；回环同学的MD作为修复说明，不能把文档当作已经跑通的程序|
|局部规划|EGO同学提供的5个规划包和消息包；接入当前仿真，不启动其另一套仿真或控制器|
|坐标桥接与控制|框架负责安装补偿、坐标对齐、控制交接，communication统一向MAVROS发指令|
|任务与验证|框架负责起飞、航点、降落、profile、基线检查、超时、日志、回放与地图导出|

~~~mermaid
flowchart LR
  S["仿真与传感器"] --> L["FAST-LIO定位"]
  L --> B["坐标桥接"]
  B --> E["EGO规划"]
  E --> C["控制适配与MAVROS"]
  C --> S
  T["任务与验收"] --> E
  T --> C
  L --> D["STD回环检测"]
  D --> P["GTSAM后端"]
  P --> M["全局路径与地图"]
~~~

现有链路：
Gazebo/PX4传感器 → FAST-LIO → bridge → EGO → control_transfer → communication → MAVROS/PX4。
FAST-LIO点云和位姿 → STD → PGO → 后端路径与地图。

全局回环修正与飞控连续里程计的完整分离、飞行中修正后的连续性，仍属于未通过项目。不能因为六个模块都启动了就说全部功能已验收。

## 2. 本轮补齐和修复的具体内容

- 统一入口 tools/framework.py：start、baseline、run、capture、report、status、view、stop。启动不自动解锁；基线通过后才运行路线；每次启动独立结果目录和PX4目录；重试必须另设标签。
- 明确控制归属：起飞前禁用规划，起飞确认后交接，降落前关闭；开启时等新的trajectory_id，避免执行上次残留轨迹。飞行中禁止重新对齐。
- 修复真实轨迹服务器首个回调dt=0导致偏航角速度NaN的问题；未来起始时刻不再误发零位置目标。
- STD静止门控放到点云积累之前，限制输入缓存并处理时间回退、过期匹配；本轮运动起始子图约万点，避免静止后积累百万点的旧问题。这不等于已经做完小时级内存稳定性验收。
- 后端地图与路径使用一致快照；地图导出不再依赖必须刚发生回环；多次实际保存成功。历史保存崩溃的所有可能原因不能据此宣称全部排除。
- 后端不再等待下一帧运动才处理末帧回环；补充拒绝候选的线程安全清理和晚到三角点处理。已用录制后端输入验证34帧、地图保存和相同拒绝结果；真正接受分支仍待有效回环数据验收。
- 飞行高度在规划占据查询和指令转发两处限制，默认0.6–1.6m；起飞、降落另行控制。两次独立绕障复测不再出现早期约0.25m的低飞。
- 每次PX4启动前生成独立rcS，external_vision使用外部位置、偏航和高度融合。空中estimator_status记录确认EV标志开启、GPS融合标志关闭；仿真GPS传感器仍存在。
- 回放分raw、submaps、backend三种模式，使用独立ROS master；算法节点不接收Gazebo真值。精确子图回放不再重复下采样。
- 提供PCD、bag、CSV、JSON与轨迹/地图图像，不用仿真世界模型冒充重建地图。

## 3. 实际实验结果

导航到达门槛与定位精度分开统计。0.5m到达成功不代表0.3m精度通过。下表距离为真实轨迹累计距离，包含起飞和降落，不能等同于预设路线长度。

|实验|结果|证据与限制|
|---|---|---|
|GPS辅助短路线|完成|2个航点；最大定位误差约0.29m|
|早期多目标路线|5个航点完成，约26.54m|部分指令含后来修复的NaN问题，保留作历史结果，不作最终平滑性验收|
|修复后的严格长路线|失败|0.3m到达未满足；另设0.5m导航实验仍在更远目标失败，停止继续放宽|
|外部定位模式早期绕障|完成|实际EGO绕过实体障碍；当时存在低飞问题，后续修复|
|高度约束绕障第1轮|完成|约12.85m；最大定位误差0.274m；路线最低真实高度0.711m|
|高度约束绕障第2轮|完成|约11.75m；最大定位误差0.299m；路线最低真实高度0.745m|
|原始隧道闭合路线|失败并降落|约55.55m后触发定位误差保护；全记录最大误差70.39m包含中止后继续发散，不能隐去|
|增加实体支柱的对照隧道|9航点完成，约63.71m|0.5m到达门槛通过；最大定位误差0.607m；2组STD候选，0条已接受回环；该场景改变不能称为原始隧道已修好|
|起点增加360°扫描的对照|失败并降落|约45.54m；第6号目标估计误差0.047m、真实到达误差0.640m，未达0.5m门槛；最大定位误差0.716m|
|独立定点复访模块测试|6圈完成，回环验收失败|真实慢速偏航；42子图、9组STD候选、0条接受；最大定位误差0.210m；未执行导航路线|

所有这些飞行尝试都记录了结果；已解锁的结束/失败飞行均记录确认降落并解除解锁。起飞失败那次未实际起飞，不能计作一次飞行完成。

## 4. 回环具体卡在哪里

完整对照隧道的精确子图回放复现了在线的两组STD候选：
- 1→32：默认重叠率约0.381，小于0.4，拒绝。
- 0→33：默认重叠率约0.750，通过几何重叠检查，但按设计等待第二组一致回环。

原代码中为Livox保留的平面ICP细化已接成默认关闭的独立选项。对同一批34个真实子图开启后，仍是第一组被单平面检查拒绝，第二组等待，0条接受。没有降低OverlapScoreThr或PlaneInlinerRatioThr，也没有注入人工约束。

定点复访确实产生9组候选，但持续触发单平面拒绝。代码的判据使用RANSAC平面距离阈值0.3m和配置的平面内点比例0.5。日志中“target cloud is like a plane”实际检查的是变换后的当前点云。为什么该场景的真实匹配仍退化，需要后续以子图几何和误匹配对照做专项标定，不能只调到接受为止。

这次已经具备：候选证据、拒绝日志、精确子图输入、后端接口录包和真值记录。下一轮可从这些数据直接定位，不必重新盲飞。优化收益需要同输入的有/无回环对照及真值核对；tools/check_loop_evidence.py不会把已有路径误报为收益。

- 编译：14个catkin包，最终增量构建通过；保留构建日志与警告。
- 8项坐标/控制回归通过；真实C++轨迹服务器独立时钟测试通过，共141条指令。
- Python语法、launch XML和git diff空白检查通过；最终检查文件见integration/final_checks_20261022。
- 原始组员交付819个文件哈希全部不变。
- 位姿桥接、EGO和控制适配器不接收仿真真值。实验驱动器用真值评价、中止，并在导航实验中门控下一航点；这个阶段门控依赖真值，不能冒充可部署的任务层。mission.py自身仅用估计里程计。
- 点云仿真当前按瞬时扫描、点内offset_time=0处理；未验证真实逐点运动畸变、实机时序、实机无GPS飞行。
- 图上的静态物体距离是机体中心到表面的距离，不是完整机体接触检测；不能宣称已经通过所有碰撞安全验收。
- 0.5m实验在满足门槛时提前进入下一阶段，不能据其0.3m标记为False推断系统在任何情况下都无法达到0.3m。
- 最新队列修复的真正接受回环分支、在线修正后飞控连续性仍未验收。

## 6. 你现在可以直接操作的内容

在WSL Ubuntu-20.04执行：
~~~bash
cd /home/zcr/uav_ws
bash tools/build_integration.sh
python3 tools/framework.py start --profile navigation_ev --scene obstacle --headless
python3 tools/framework.py baseline
python3 tools/framework.py run --route obstacle --arrival 0.5
python3 tools/framework.py capture
python3 tools/framework.py view
python3 tools/framework.py report
python3 tools/framework.py stop
~~~

start只启动，run会实际起飞。每次run前确认基线通过。失败重跑加 --label 新名称，保留旧结果。
只看定位和建图可用 --profile mapping；该模式不会自动飞一圈。运动采集后才能重建沿途地图。

文件位置：
- README.md：入口；
- docs/ARCHITECTURE.md：模块、坐标和分工；
- docs/EXPERIMENTS.md：参数、复现、回放和停止条件；
- integration/session_20261022.json：全部数据目录清单；
- integration/runs/*：每次启动的日志、地图、轨迹和原始数据；
- integration/replays/*：独立回放，不能覆盖在线结果；
- integration/final_checks_20261022：最终检查、代码差异、原始文件保护检查。

## 7. 后续优先顺序
